# v0.2 第一期：三种数据库接入适配

日期：2026-10-23。用户已要求将本计划与[Gateway 计划](v0.2-gateway-sessions.md)作为本期的两个阶段实施。
本文定义第一阶段的数据库接入交付；会话业务和 Gateway 在第二阶段实施。

## 范围

第一阶段只完成 **SQLite、PostgreSQL、MySQL** 的接入适配：

- 后端选择、连接配置校验、连接建立、健康检查、关闭与资源释放。
- SQLite 文件/目录与连接选项；PostgreSQL/MySQL 的连接超时、连接池及连接选项。
- 明确事务边界，验证提交、回滚、Unicode 数据及参数绑定的共同基础行为。
- 各后端必要的初始化设置与能力检查；配置或连接失败明确报错，不自动回退到另一种数据库。
- 统一的最小接入接口和同套集成测试，数据库差异限制在适配层内。

不在数据库阶段实现 SessionStore 会话业务、sessions/messages 表、消息编解码、历史恢复、
Gateway、HTTP/SSE、Web UI、跨库数据迁移、其他数据库、多实例协调或生产部署。
数据库环境的建库建用户由 Compose 显式完成，不要求应用启动使用管理员权限。

## 准备与实现顺序

1. **开发环境（本次）**：Mertina 与测试直接在本地运行；SQLite 文件默认放在
   `/Users/mac/Desktop/Metina/mertina_dev.sqlite3`，不同分支可使用不同文件名。
   PostgreSQL/MySQL 使用独立 Compose 项目、已有镜像和命名卷，端口仅绑定 loopback。
2. **接入契约与依赖评估**：确定最小接口、配置、超时、事务/取消语义、异常与日志脱敏。
   SQLAlchemy Core 异步 engine 是候选，异步驱动和版本在此时评估，再更新 `pyproject.toml`/`uv.lock`。
   不因预期后续业务而提前建立通用 DAO 或空壳会话框架。
3. **实现与验证**：逐个交付 SQLite → PostgreSQL → MySQL；全部通过统一的接入契约测试，
   再宣布数据库阶段完成。三种均为必交付后端，顺序不表示 MySQL 可选。
4. **后续期**：另行定义会话表、版本化 schema 初始化/升级与业务存储契约，再接 Gateway。

数据库选择及嵌入式/服务端部署边界记录于 [ADR 0001](../adr/0001-database-backends.md)。
之前的两份数据库调研保留为研究参考，不再用于推定第一期要完成整个会话系统。

## 第一期开工与完成检查

- 开工前：环境可重复启动，记录实际版本；SQLite 文件放在指定的仓库外目录中。
- 完成时：三种后端都有成功连接、无效配置、连接失败、资源释放和事务回滚测试。
- SQLite 验证文件重开、外键开关、busy timeout 及选定 journal 模式；MySQL 验证 utf8mb4/InnoDB；
  PostgreSQL 验证实际用户可读写指定数据库。约束语义按选定接口补充测试。
- 明确取消时回滚、失效连接处置及安全错误分类；日志和异常不暴露凭据或完整 DSN。
- 网络数据库集成测试使用本项目隔离库；SQLite 自动化测试使用临时文件；不接其他项目数据。
- 实现后在本地环境执行 Ruff、mypy、单元/三后端集成测试和构建，依赖按锁文件安装。

环境命令见 [dev/databases](../../dev/databases/README.md)。本次环境验证不计作适配器验收。

## 本轮目录约定

三个后端专属代码分别位于 `src/mertina_agent/database/sqlite/`、`postgresql/`、`mysql/`。
共享连接生命周期、配置与错误边界位于 `database/`；会话业务仍放在 `state/`。
单元测试按同一结构放在 `tests/unit/database/`；真实数据库契约测试放在 `tests/integration/database/`。
阶段结果记录在 `docs/testing/v0.2-phase-1/`，执行记录见 `v0.2-development-log.md`。
