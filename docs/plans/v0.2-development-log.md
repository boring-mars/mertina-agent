## 开发者 CLI

2026-11-10，按用户要求在 `feat/cli` 分支上新增一个方便开发的 `mertina` 命令（`src/mertina_agent/cli.py`），
不是 P2 规划中的本地客户端：

- 不带参数的 `mertina`（或 `chat`、`run`）在 CLI 进程内直接运行 Agent，逐轮落库，可以 `--resume` 续聊；
  另有 `sessions`、`db init|check`、`gateway` 子命令，后两个包装原有的 `python -m` 入口。
- 配置文件查找顺序：`--env-file` > `./.env` > `~/.mertina/.env`；环境变量始终优先。
- 第一次 Ctrl+C 协作停止并保存已生成的内容，第二次放弃本轮且不保存。
- 把判断一轮以何种状态结束的逻辑抽成 `state.serialization.turn_status()`，CLI 与 Gateway 共用。

实现中发现并修复了 Gateway 的一个问题：提交时如果存储因历史版本变化而明确拒绝（`SessionConflictError`，
另一进程改写或删除了会话），原代码把它当成结果未知，标记需要核对且不释放会话锁，
导致该会话在 Gateway 中一直返回 409，并持续占用活动名额。现在按明确失败处理（`history_conflict`），
释放锁，并补了回归测试。单进程内由会话锁保证不会出现这种冲突，CLI 与 Gateway 同时写同一会话时才会触发。

验证：CLI 单元测试与 SQLite 集成测试（含真实 SIGINT 停止和放弃轮次）；在仓库外的目录用本地假模型
手动跑通了未初始化提示、`db init`、两轮对话、`/sessions`、`run --resume` 续聊和不存在会话的报错。
