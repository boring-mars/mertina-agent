## 2. W1：迁移来源与 SDK 验证

- Hermes 源 SHA：`9d24f9c91f3bf6b9faad5436cb12d20a8c7d46a1`。
- [来源及删减矩阵](../sources/hermes-model-transport.md) 记录具体符号及本项目改造。
- 完整 MIT 许可保存到 `LICENSES/Hermes-Agent-MIT.txt`；Git blob SHA 与上游一致：
  `75410e73319c72cd3e991a501c5455eb78f38375`。
- 锁定 OpenAI SDK **3.16.2**（Python >=3.10，Apache-2.0）作为运行时依赖。
  当前 SDK 使用 HTTPX2；直接使用的 **httpx2 2.13.0**（Python >=3.10，BSD-3-Clause）
  已显式列入 dev 依赖，测试使用 `MockTransport`，不访问真实模型。
- 通过离线契约实验核实 `with_options` 覆盖地址、key、超时、重试，且不修改原实例；
  派生实例共享 HTTP 资源，因此 ModelClient 不关闭注入实例或其派生视图。
- None/空 key 使用内部非敏感占位值满足 SDK 构造要求，再通过 `Omit` 删除实际请求的
  Authorization；测试放置环境诱饵凭据并检查序列化后的 HTTP 请求。
- SDK 3.x 还会读取环境自定义 headers；请求边界清除这些继承值，只发送受控请求头。
- 实验发现：底层 HTTP 客户端自带的 Authorization/Basic auth 可绕过 SDK 的 Omit。
  因而对这种注入配置在构造时拒绝，不修改外部 HTTP 对象，也不冒险发送。
  唯一 SDK 私有字段访问局限于读取 `_client` 做兼容性检查，已注释并纳入回归测试。
- 通过 SDK 公共 `with_raw_response.create` 获取原始 JSON，再做严格结构校验。
  SDK 的请求发送、状态错误及超时处理仍然复用；不依赖 SDK 宽松模型充当本项目协议验证器。
- 独立复查发现 SDK 默认跟随 307 重定向，`max_retries=0` 仍可能发出两次 HTTP 请求。
  自有客户端显式使用 `DefaultAsyncHttpxClient(follow_redirects=False)`；注入客户端若启用
  自动重定向则在构造时拒绝。重定向交由调用方处理，本阶段不隐式发起下一次请求。
- URL query 在 SDK 路径拼接时会形成错误路由；现在构造前拒绝 URL query/fragment，
  不悄悄修改调用方提供的端点。

## 3. 注释与维护约定

源码使用英文 Google-style docstring，重要注释解释“为什么”：

- 不修复模型给出的 arguments，不补造工具 ID，不把未知用量伪装成零。
- 不将 refusal、截断或过滤重新标为普通完成。
- 不自动重试，避免将来 Agent 的重试策略与 SDK 叠加。
- 区分自有与注入 SDK 的资源所有权；取消异常自然传播。
- 错误只展示受控消息；原始异常链仅供可信调试，不直接打印给用户。
