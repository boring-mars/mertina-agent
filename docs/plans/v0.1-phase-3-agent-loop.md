# v0.1 第三阶段开发计划：Agent 循环核心（分检查点）

编制日期：2026-09-21。状态：已批准，按检查点实施中。
来源与删减记录见 [hermes-agent-core.md](../sources/hermes-agent-core.md)。

本计划取代同名早期草案：早期草案主张“提取职责后按 Mertina 重写”，本版改为尽可能保留 Hermes
代码与结构，只删去 v0.1 不需要的分支。

## 背景

第二阶段交付了异步 `ModelClient` 与 Chat Completions transport（`be2b655`）。第三阶段要把 Hermes
最重的 agent loop 迁进来，让一个 `Agent` 实例可以创建并进行 ReAct 式（模型 → 工具 → 模型）对话，
最终满足 ROADMAP v0.1 的 Done-when：web_search 闭环脚本；fake 模型覆盖普通回答/工具/并行/预算/
重试/中途停止；停止后历史可继续。

迁移量极大（Hermes 相关路径约 2 万行），因此本阶段拆成 7 个检查点（CP0–CP6），每个都可独立验收、
独立提交、仓库保持全绿。原则是**尽可能保留 Hermes 代码与结构**：保留 Hermes 的模块
名、phase 拆分、verdict 返回模式（`fallthrough/continue/break/return`）、常量文本与关键算法，
只砍掉 v0.1 不需要的分支。

已定决策（2026-09-21 确认）：
- **异步循环**：`await agent.run_conversation()`；Hermes 的线程机制按 asyncio 等价改写（见 §3）。
- **搜索 provider：ddgs**（无 key），连同 Hermes 的“可杀子进程”隔离一起迁移。
- **预算耗尽：保留 Hermes 的 summary 调用**（一次无工具请求，给用户一个答复）。
- 沿用既有决定：`Agent` 是普通类（`agent/core.py`），不用 14 个 Mixin；phase 函数接显式参数，
  不用 `_run_phase` 反射 `_LoopState`；`prompt_builder.py` / `system_prompt.py` 保持分离。

## 3. 跨检查点的硬约束

**历史不变量**（每个检查点都要有测试守护）
- 历史里只存第二阶段 transport 能接受的 `ChatMessage` TypedDict：tool 消息不带 Hermes 的 `name`/`tool_name`，
  assistant 不带 `finish_reason`/`reasoning`（Hermes 在 `build_api_messages` 里弹掉，Mertina 直接不存）。
- 每个 assistant `tool_calls` 恰好对应一条同 ID 的 tool 结果，顺序与调用顺序一致。
- 停止/失败后不以 `tool` 结尾（`close_interrupted_tool_sequence`），不以 `user` 结尾（`_close_durable_failed_turn`），
  返回的 `messages` 可直接作为下一轮 `conversation_history`。
- 调用方传入的 history 列表与字典不被原地修改。

**异步改写对照**（Hermes 语义不变，只换机制）
- `_interrupt_requested` 布尔 + 一个 per-run `asyncio.Event`；`interrupt()` 在同一 event loop 调用，跨线程走 `call_soon_threadsafe`。
- 请求中断：模型请求 task 与中断事件 `asyncio.wait(FIRST_COMPLETED)` 赛跑，中断则取消请求（对应 Hermes `_interruptible_api_call`）。
- 退避：`asyncio.wait_for(event.wait(), timeout=wait)` 替代 200ms 轮询 sleep。
- 并行工具：`asyncio.gather`；同步 handler 走 `asyncio.to_thread`；ToolEntry 保留 `is_async`。
- 工具侧中断：contextvar 指向当前 run 的中断状态，`agent.interrupt.is_interrupted()` 对工具透明。
- `CancelledError` 始终传播，不伪装成模型错误。

**结果契约**：`run_conversation()` 返回 `ConversationResult` TypedDict，键名沿用 Hermes：
`final_response`、`messages`、`api_calls`、`completed`、`failed`、`interrupted`、`partial`、
`turn_exit_reason`、`error`（可选）、`usage`（汇总）。`chat()` 返回 `final_response`。

**配置新增**（`config.py`，env-first，同步 `.env.example`）：`MERTINA_LLM_MAX_ATTEMPTS`（默认 3，对应 Hermes
`api_max_retries`，≥1）、`MERTINA_LLM_STREAM`（默认 true）、`MERTINA_WEB_SEARCH_BACKEND`（`Literal["ddgs"]`）、
`MERTINA_WEB_SEARCH_TIMEOUT_S`（默认 30）。已有 `MERTINA_MAX_ITERATIONS` 开始生效。

**风格**：每个迁移文件头注明 Hermes 来源路径与 SHA、MIT 署名；英文 Google docstring、`X | None`、行宽 100、
无 `print()`、异常统一放 `exceptions.py`（新增 `ToolRegistrationError` 等）。测试放 `tests/unit/` 镜像目录，
只在边界 mock（模型用 `ModelClientProtocol` 的脚本化 fake，搜索用 fake provider / 假子进程）。
异步测试沿用第二阶段做法：`asyncio.run` 包装，不新增测试插件。

## 5. 风险与预案

| 风险 | 预案 |
|---|---|
| 异步改写悄悄改变 Hermes 语义 | 来源文档逐符号写明“机制变了、语义不变”；中断/退避/并行各有对应 Hermes 测试意图的回归 |
| ddgs 依赖或 DuckDuckGo 限流导致真实验收不稳 | 离线测试全部用假 worker；integration 失败单独记录，不阻塞离线门禁；provider 接口保证后续可换 |
| 历史契约与 Hermes 不同（无 name/finish_reason） | CP1 起用不变量测试守护；finish_reason 放在 per-turn 状态而非历史 |
| CP2 体量大 | CP2 内部按 phase 文件逐个落地，每个 phase 先写其 verdict 单测；如需要可再拆 CP2a（循环 + 纯文本）/ CP2b（工具轮次） |
| 预算 summary 额外请求超出 `max_iterations` | 文档与结果中明确：summary 是一次无工具的收尾调用，`api_calls` 如实计数 |
