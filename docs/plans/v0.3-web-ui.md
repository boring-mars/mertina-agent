## 1. 目标与范围

v0.3 交付一个由 Gateway 进程直接提供的浏览器界面：在浏览器里发起对话、看到流式回答和工具调用、随时停止，
浏览和管理历史会话；刷新页面后能重新接上正在运行的回答。

| 功能块 | 交付内容 | 对应原型截图 | 主要依赖的已有能力 |
|---|---|---|---|
| 应用外壳 | 三区布局、亮暗主题、手机布局、Gateway 连接状态 | 01、15、16、17 | 本机回环与同源校验、统一错误信封 |
| 会话管理 | 列表、新建、重命名、删除可撤销、`⌘K` 搜索跳转、后台运行与未读提示 | 01、11、12、14 | `/api/sessions/*`、`metadata_version`、`active_run_id` |
| 消息与输入 | 历史消息回放、Markdown 渲染、每会话草稿、生成中排队一条 | 01、06、14 | `GET .../messages`、`POST /v1/runs` |
| 运行与流式 | 阶段进度条、流式正文、停止、终态与"已保存" | 03、05、07 | `/v1/runs`、SSE、`stop`、`run.committing` |
| 工具调用 | 并行进度、成功后折叠、出错标红并保持展开 | 02、10 | `tool.generating/started/finished` |
| 出错与恢复 | 重试倒计时、失败与重发、保存未确认、断线续订与重新同步 | 04、07、08、09 | `retry.scheduled`、错误码、`Last-Event-ID`、`409 resync_required` |
| 详情面板 | 本轮状态与时间线、事件流 | 01、13 | 运行快照与事件信封 |

**不纳入 v0.3**：原型里的"演示场景"标签页；终端、Diff 审批等 P1 工作台组件；记忆与技能界面（v0.4）；
认证与多用户；把 `web/dist` 打包进 Python wheel；跨会话事件推送（后台完成提醒用轮询实现）。

## 2. 已确定的决策

以下决策来自 RFC #9 与 v0.3 方案评审，实施时不再重新讨论。

| 主题 | 决策 |
|---|---|
| 界面来源 | 自研，按 RFC 原型实现；**不再沿用 Hermes 的 `web/` 外壳**。ROADMAP 与 README 同步修改 |
| 技术栈 | React 19 + TypeScript（strict）+ Vite + Tailwind CSS v4 + shadcn/ui；图标 `lucide-react` |
| 状态 | 运行事件由**不依赖 React 的纯函数 reducer** 处理，Zustand 只保存其结果；会话与消息等 REST 数据用 TanStack Query |
| 流式传输 | 保持 v0.2 的 HTTP + SSE，不引入 WebSocket；用 `fetch` + `ReadableStream` 读取 SSE，不用 `EventSource` |
| Markdown | `react-markdown` + `remark-gfm`；**不启用 `rehype-raw`**；保留 `react-markdown` 默认的 `urlTransform`（会拦掉 `javascript:` 等危险链接）；外链加 `rel="noopener noreferrer"`。理由：`web_search` 读到的网页可以对模型做提示注入，让回答夹带 HTML（如 `<img onerror=...>`）。开了 `rehype-raw`，这段 HTML 会在 Gateway 同源页面里执行，从而绕过 Host/Origin 校验，读取、删除会话或外传数据；P0 没有鉴权，这道校验是唯一防线。以后真要支持部分 HTML，必须接 `rehype-sanitize` 白名单 |
| 代码高亮 | shiki 按需懒加载：首次出现代码块时再加载高亮器和对应语言 |
| 字体 | 用 `@fontsource` 自托管 Inter 与 JetBrains Mono，不访问 Google Fonts 等外部 CDN |
| 删除会话 | 按 RFC：删除后 5 秒内可撤销，前端延迟发送 `DELETE`；不做弹窗二次确认 |
| 视觉 | 采用原型的暖色 Token（亮/暗两套），迁移为 Tailwind v4 `@theme` 中的 CSS 变量 |
| 构建产物 | `web/dist` 不提交进仓库；Gateway 发现 `dist` 存在就托管，不存在就在日志里提示构建命令 |
| 联调数据库 | 开发与联调优先用 SQLite；三种数据库的兼容性仍由现有 Python 测试保证 |

## 4. 前端运行状态机

### 4.1 事件 reducer

`reduceRun(state, event) -> state` 是整个前端最核心、最容易出错的部分，要求：

- 纯函数，不读时钟、不发请求；时间由调用方随事件传入。
- 覆盖 v0.2 的全部事件：`run.accepted`、`run.started`、`tool.generating`、`tool.started`、`tool.finished`、
  `text.delta`、`retry.scheduled`、`run.stop_requested`、`run.committing`，
  以及四种终态 `run.completed`、`run.partial`、`run.stopped`、`run.failed`。
- `retry.scheduled`：把已有正文转为"过期草稿"（变淡划掉），等下一个 `text.delta` 到达后再替换；同时记录倒计时。
- 未知事件类型忽略并保留在事件流面板中，不抛错，以便 Gateway 新增事件时旧前端仍能工作。
- 用录制的事件序列做表驱动单元测试，每种事件、终态和续订分支都要有用例（见第 7 节）。

原型中的 [`apply(run, type, data)`](https://github.com/boring-mars/mertina-agent/blob/web-ui-prototype/index.html)
可作为参考实现。

### 4.2 订阅、续订与重新同步

1. 打开会话：`GET /api/sessions/{id}` 拿到 `active_run_id`，同时分页加载历史消息。
2. 有运行中的回答：从 `Last-Event-ID: 0` 订阅事件流，重放缓冲中的全部事件。
3. 连接断开：带最后收到的事件 ID 续订，指数退避，上限 10 秒。
4. 返回 `409 resync_required`，或流里出现 `event: resync_required`：拉 `GET /v1/runs/{id}` 快照，
   用快照的 `text` 覆盖正文，再从快照的 `last_event_id` 续订。
5. `GET /v1/runs/{id}` 返回 404（运行已过期或 Gateway 重启）：重新读取会话消息，以数据库为准。

已知限制：v0.2 每个模型流片段都发一个 `text.delta`，长回答很容易超过默认 256 条的事件缓冲。
一旦走到第 4 步，快照里只有正文，**运行中的工具卡片会丢失**。修复方式见第 5.2 节的协议补充。

### 4.3 终态处理

| 终态 | 界面 | 之后 |
|---|---|---|
| `completed` / `partial`，`durable: true` | 底部显示"已保存 · rev N"；`partial` 额外提示回答未正常结束 | 重新读取该轮消息，以数据库为准 |
| `stopped`，`durable: true` | "已停止 · 已保存"，提供"继续生成" | 同上 |
| `stopped`，`durable: false` | 在开始前就停止，没有写入 | 把用户消息退回输入框 |
| `failed` + `model_failed` | 显示失败原因和"重新发送"；**这一轮已保存**，数据库里会多一条"请求未处理"的助手消息，照常渲染 | 重新读取消息 |
| `failed` + `run_failed` / `history_conflict` | 显示失败原因；**没有写入**，用户消息保留在本地并标为"未发送" | 提供"重新发送" |
| `failed` + `storage_unconfirmed` / `shutdown_cancelled`，`reconciliation_required: true` | "保存结果未确认"，禁止直接重发，引导重新读取会话 | 该会话在 Gateway 重启前一直被占用，界面需说明 |

终态之后若会话有排队的消息，自动发送；失败时把排队消息退回输入框，不自动发送。

### 4.4 历史消息的渲染

数据库里的一轮是平铺的 `user` → `assistant(tool_calls)` → `tool` → `assistant(text)`。前端按轮次把它们合并成
与实时状态一致的"工具卡片 + 正文"。

已知限制：数据库**没有保存工具耗时和是否出错**，所以历史中的工具卡片只显示工具名、参数和返回内容，不显示耗时。
v0.3 接受这个限制，不为此改动存储结构。

## 5. Gateway 侧改动

这些改动都是 Python 代码，放在一个单独的 PR 里（第 9 节 CP1），方便后端同学审阅。

### 5.1 静态托管

- `create_app()` 在 `web/dist` 存在时挂载静态文件，`index.html` 作为 SPA 回退。
- 回退只作用于 `GET` 且不以 `/api/`、`/v1/` 开头的路径；API 的 404 仍返回 JSON 错误信封。
- `web/dist` 不存在时启动不报错，日志提示构建命令；静态目录路径可通过配置覆盖，便于测试。
- 静态响应加上 `Content-Security-Policy`（只允许同源脚本、样式与字体）和 `X-Content-Type-Options: nosniff`。
- 静态请求同样经过 `_check_local_request` 的 Host/Origin 校验。

### 5.2 协议补充

以下全部是新增字段或接口，不改变现有字段的含义，不影响现有客户端。逐条的需求与测试场景在 CP1 的 PR 中给出：

1. `tool.started` 带上参数 `arguments` 与 `arguments_truncated`（超过 4096 字符时整体置空）。
2. 终态事件加上 `text_truncated`、`finished_at_us`；快照加上 `accepted_at_us`、`finished_at_us`。
3. **快照加上本轮的工具调用列表**（`call_id`、`name`、状态、耗时、`is_error`、参数），解决第 4.2 节重新同步后工具卡片丢失的问题。
4. 新增 `GET /api/sessions/{id}/commits/{operation_id}`，Gateway 重启后仍能核对"保存未确认"的一轮。
5. **会话列表支持按最近更新倒序**：新增 `order=updated_desc`，游标为 `(updated_at_us, id)`。
   当前按创建时间升序分页，每页最多 100 条，最新的会话总在最后一页，前端无法只拉第一页。
   `updated_at_us` 目前没有索引；单用户的会话表很小，排序开销可以忽略，v0.3 不加索引，避免给已有数据库引入迁移。

## 6. 开发与联调

### 6.1 本地运行

- **开发**：`npm --prefix web run dev` 启动 Vite，代理 `/api` 与 `/v1` 到 `127.0.0.1:8765`。
  代理必须同时改写 `Host` 和 `Origin`：`changeOrigin` 只改写 `Host`，`Origin` 要在代理的 `proxyReq` 钩子里设置，
  否则会被 Gateway 以 `403 forbidden_origin` 拒绝。不放宽后端校验。SSE 响应不能被压缩或缓冲。
- **一条命令运行**（满足 ROADMAP 验收标准）：`npm --prefix web run serve`，依次执行 `npm ci`、构建、
  `uv run mertina gateway`。README 写明这条命令。
- **数据库**：独立的 SQLite 文件，例如 `MERTINA_DATABASE_URL=sqlite+aiosqlite:////tmp/mertina-web.sqlite3`，
  配合 `MERTINA_GATEWAY_BOOTSTRAP=true` 自动建表。

### 6.2 假模型

日常开发与自动化测试用 [`dev/e2e/stub_model.py`](../../dev/e2e/stub_model.py)，配合
[`dev/e2e/serve_gateway.py`](../../dev/e2e/serve_gateway.py) 提供的确定性 `lookup` 工具，不花模型费用。
现有标记只有 `[tool]`、`[slow]`、`[long]`，需要补充以下标记才能稳定复现原型的全部状态：

| 标记 | 行为 | 复现的状态 |
|---|---|---|
| `[parallel]` | 一次返回两个 `lookup` 调用 | 并行工具（图 02） |
| `[toolerror]` | `lookup` 返回失败结果 | 工具出错（图 10） |
| `[retry]` | 第一次请求返回 429 和 `Retry-After`，同一请求第二次正常回答 | 重试倒计时（图 04） |
| `[fail]` | 始终返回 503（可重试状态码，会先经历重试再失败） | 模型失败（图 07） |
| `[tokens]` | 以大量单字片段慢速输出，超过 256 条事件缓冲 | 断线后 `409 resync_required`（图 09） |

`[retry]` 需要按请求内容记住尝试次数，是假模型里唯一有状态的行为，在文件说明里注明。

"保存未确认"（图 08）依赖写库时的存储故障，用 Python 集成测试覆盖，不在浏览器里复现。

### 6.3 真实模型

用真实模型做验收，并录制正常流程的事件序列作为测试 fixture，以真实的片段大小和节奏校准 reducer。

目前还没有录到真实模型的事件序列，在 CP2 中补录。2026-11-28 的一次尝试（请求被提供方拒绝）确认了一点：模型调用失败时这一轮仍会保存（`durable: true`），并写入一条"请求未处理"的助手消息。

## 10. 风险与待定事项

- **[事件缓冲]** 第 5.2 节第 3 项落地前，长回答断线后工具卡片会丢失。缓解：CP1 中实现；在此之前可临时调大 `MERTINA_GATEWAY_EVENT_CAPACITY`（上限 2048），同时把 `MERTINA_GATEWAY_SUBSCRIBER_CAPACITY` 调到不小于它，否则配置校验会失败。
- **[保存未确认占用会话]** `storage_unconfirmed` 的运行会一直占用会话直到 Gateway 重启。回执接口能告诉用户结果，但不会释放会话。是否新增"核对后释放"的接口，在 CP5 根据实际体验决定。
- **[shiki 体积]** 懒加载后首个代码块会有短暂的无高亮状态。缓解：先显示纯文本代码块，加载完成后再替换，不闪烁布局。
- **[真实模型 fixture]** 需要可用的模型凭据才能录制；在此之前 reducer 测试只能用假模型录制的序列。
