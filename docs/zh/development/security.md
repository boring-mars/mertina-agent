# 安全

[English](../../en/development/security.md) | **中文**

Mertina Agent 运行在云端，处理用户凭证，并运行可以调用工具的 LLM agent。
安全问题会直接影响真实用户，所以这些规则不是可选的。

## 报告漏洞

**不要通过公开的 issue、PR 或 Discussion 报告安全漏洞。**

- 通过 GitHub 私下报告：进入仓库的 **Security** 页面，选择 **Report a vulnerability**
  （私密漏洞报告）
- 请提供漏洞描述、受影响的版本、复现步骤和潜在影响
- 维护者会在 **3 个工作日**内确认收到报告，并持续告知修复进展
- 修复在私密的安全公告（security advisory）中进行，发布修复版本后再公开公告。
  除非报告者不希望署名，否则会在公告中致谢
- 请在公开披露之前给我们合理的修复时间（通常不超过 90 天）

只有最新版本会收到安全修复。

## 密钥

- **绝不提交密钥**：API key、token、密码、私钥、云服务凭证、带密码的连接字符串
- 配置从环境变量读取。`.env` 已加入 `.gitignore`，只提交使用占位值的 `.env.example`
- 测试和示例使用明显是假的值（`sk-test-000`），绝不使用真实的值
- 仓库开启了 GitHub **secret scanning** 和 **push protection**。如果推送被拦截，请删除密钥，不要绕过检查
- **密钥一旦被提交，哪怕只是在分支上、哪怕只存在了一分钟，都要当作已经泄露处理：**
  1. 立即到服务提供方吊销或轮换这个密钥。只有这一步才能真正解决问题
  2. 通知维护者
  3. 从 git 历史中删除是次要的，因为它很可能已经被复制走了
- CI 使用的密钥保存在 GitHub Actions secrets 中，权限范围尽量小。
  由 fork 提交的 PR 触发的工作流无法访问这些密钥

## 安全编码规则

**输入与注入**
- 在系统边界校验所有外部输入：类型、长度、格式、允许的取值
- 使用参数化查询，绝不通过字符串拼接构造 SQL
- 绝不把用户输入传给 shell。确实需要运行子进程时，使用参数列表，不要用 `shell=True`。
  如果实在无法避免拼接 shell 字符串，每个插入的值都要用 `shlex.quote()` 转义
- **先**解析文件路径（包括符号链接，使用 `Path.resolve()`），**再**检查它是否仍在预期目录内
  （`resolved.is_relative_to(base)`）
- 不要用 `pickle`、`yaml.load`（请用 `yaml.safe_load`）或 `eval` 处理不可信的数据

**认证、授权与租户**
- 除非明确是公开的（例如健康检查），每个接口都需要认证
- 每个请求都要在服务端检查授权，不能依赖客户端
- 所有涉及用户数据的查询都要限定在当前租户或用户范围内，并且要测试一个租户无法访问另一个租户的数据
- 比较密钥时使用 `hmac.compare_digest`，而不是 `==`

**LLM agent 与工具**
- 把模型的输出当作不可信的输入，执行工具之前先校验参数
- agent 获取的内容（网页、文件、工具结果）可能包含提示注入。不能让这些内容扩大 agent 的权限，
  也不能在没有显式检查的情况下触发敏感操作
- 工具以完成任务所需的最小权限运行。代码执行和文件访问要放在沙箱中
- 对每个请求的步数、token、时间和费用设置上限，防止失控

**数据**
- 只收集和保留必要的数据
- 传输中的数据加密（TLS），存储使用云服务商提供的静态加密
- 不记录密钥、token、包含用户数据的完整提示词或个人数据（参见[编码规范](coding-style.md#日志)）
- 返回给客户端的错误信息不包含堆栈信息或内部细节

**密码学**
- 使用成熟的库（`secrets`、`hashlib`、`cryptography`），绝不自己实现加密算法
- 生成不可猜测的 token 和 ID 时，使用 `secrets` 而不是 `random`

## 依赖与供应链

- 依赖版本锁定在 `uv.lock` 中，保证所有人和 CI 安装的版本一致
- Dependabot（或 Renovate）会自动提交依赖更新的 PR，安全更新优先审查和合并
- 开启 Dependabot alerts，及时发现依赖中的已知漏洞
- 新依赖要像代码一样审查：维护状况、流行程度、许可证，以及包名是否拼写正确（防止仿冒包）
- 工作流中使用的 GitHub Actions 要固定到 commit SHA 或可信的主版本，
  工作流只声明所需的最小 `permissions:`
- 通过 Trusted Publishing 发布到 PyPI，不存在可以被窃取的长期 token

## 安全审查

以下模块的改动需要熟悉该模块的人审查：

- 认证、授权、会话
- 租户隔离和数据访问
- 密钥处理和配置
- 工具执行、沙箱，以及任何运行用户或模型提供的代码的地方
- 部署配置、网络暴露、IAM 权限
