# Issue 与标签

[English](../../en/development/issues-and-labels.md) | **中文**

## 开 issue 之前

- 搜索已有的 issue，包括已关闭的
- **安全漏洞绝不能在公开 issue 中报告**，参见[安全](security.md#报告漏洞)
- 一般性的问题和尚不具体的想法，请用 Discussions（如果已开启），而不是 issue

## 报告 bug

好的 bug 报告能让别人复现问题。请包含：

- **版本**：Mertina Agent 的版本或 commit、Python 版本、操作系统、部署方式
- **复现步骤**：能复现问题的最少步骤或最少代码
- **期望行为**和**实际行为**
- **日志和错误信息**：用文本而不是截图，并且**删除其中的密钥、token 和个人数据**
- 你已经尝试过的方法

## 功能建议

先描述**问题**，再描述方案：

- 你想做什么？现在为什么难以做到？
- 你希望实现什么效果？
- 你考虑过哪些替代方案？
- 你愿意自己来实现吗？

功能建议是一个提案。在提交大的实现 PR 之前，需要先达成一致（打上 `accepted` 标签）。

## issue 生命周期

```
新建 ──► 分流 ──► 等待信息 ──► ...
          │
          ├──► 已接受 ──► 进行中（已指派 / 已关联 PR）──► 由 PR 关闭
          │
          └──► 关闭（重复 / 不修复 / 无效）
```

- **分流（triage）**：协作者给新 issue 打上类型标签，可能的话再打上优先级。争取一周内完成分流
- **等待信息**：如果报告者 14 天内没有回复，issue 可能会被关闭。补充信息后可以重新打开
- **指派**：留言认领 issue 后会被指派给你。如果 30 天没有进展，
  可能会取消指派，让其他人接手
- **关闭**：issue 由修复它的 PR 自动关闭（`Closes #12`）。因为其他原因关闭时，要附上简短的说明

## 标签

标签按用途分组如下。标签数量要保持精简，新增标签需要说明理由。

**类型**（每个 issue 一个）

| 标签 | 含义 |
|---|---|
| `bug` | 功能与文档描述不符 |
| `enhancement` | 新功能或改进 |
| `documentation` | 仅文档 |
| `question` | 提问，而不是修改请求 |
| `security` | 安全加固（不包括未公开的漏洞） |

**状态**

| 标签 | 含义 |
|---|---|
| `needs-triage` | 还没有协作者看过 |
| `needs-info` | 等待报告者补充信息 |
| `needs-discussion` | 方案尚未达成一致 |
| `accepted` | 已确认要做，可以认领 |
| `blocked` | 被其他事情阻塞 |

**优先级**（可选）

| 标签 | 含义 |
|---|---|
| `priority: high` | 严重 bug、数据丢失、安全问题，或者影响很多用户 |
| `priority: low` | 有了更好，没有也行 |

**面向贡献者**

| 标签 | 含义 |
|---|---|
| `good first issue` | 范围小、定义清楚，适合作为第一次贡献。要附上相关代码的位置提示 |
| `help wanted` | 维护者欢迎外部贡献 |

**处理结果**

| 标签 | 含义 |
|---|---|
| `duplicate` | 已经有人报告过，附上原 issue 链接 |
| `wontfix` | 不会处理，需要说明原因 |
| `invalid` | 不是 bug，或者信息不足以处理 |

**其他**

| 标签 | 含义 |
|---|---|
| `breaking` | 涉及破坏性变更 |
| `dependencies` | 依赖更新（Dependabot / Renovate 使用） |
| `flaky-test` | 时好时坏的测试 |
