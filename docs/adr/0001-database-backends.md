# 0001：第一期支持 SQLite、PostgreSQL、MySQL

日期：2026-10-23。状态：用户已确定支持名单和第一期范围；本地记录待随 PR 评审。

## 背景

原路线图指定 SQLite，会话持久化调研讨论过更多数据库。用户现已明确第一期只完成
SQLite、PostgreSQL、MySQL 的接入适配。用户进一步明确：Mertina 与分支测试在本地运行，
SQLite 文件集中放在 `/Users/mac/Desktop/Metina/`，减少开发用容器和镜像需求。

## 决定

- 首批仅支持这三种数据库；第一期做接入层，后续再实现会话存储和 Gateway。
- 一个配置选择一个后端；连接失败不回退，不自动迁移数据。
- SQLite 由本地 Mertina 进程直接打开文件，开发库默认路径为
  `/Users/mac/Desktop/Metina/mertina_dev.sqlite3`；分支测试可分别配置独立文件。
  PostgreSQL/MySQL 使用各自服务容器和独立命名卷，不复用其他项目的数据库。
- 容器环境使用现有 `postgres:18`、`mysql:8.0` 镜像作为开发基线；SQLite 使用本地 Python 标准库。
  镜像实际版本由验证记录给出，不据此承诺未经测试的最低版本或整个版本区间。
- SQLAlchemy Core/异步驱动为候选技术方案，具体依赖另行评估；本次不新增应用依赖。

## 考虑过的方案

- 只做 SQLite：不能满足三种适配的范围。
- SQLite 工具容器与命名卷：增加本地应用访问文件及测试环境的复杂度，本轮改为本地文件。
- 给 SQLite 加网络代理：改变原生接入方式并引入额外协议，第一期不采用。
- 复用其他项目的 PostgreSQL/MySQL 库：会混入其他数据和权限，改用独立容器。

## 影响

SQLite 不需要启动服务或占用端口；文件及 WAL/SHM 伴随文件集中放在指定本地目录。
该路径是本机开发约定，应用接入层实现时应支持配置覆盖，不能把开发机绝对路径硬编码进库。
开发基础设施就绪与应用适配完成分别验收；后续三种后端必须通过同套接入契约测试。
SQLite 本地文件不受 Compose 清理影响；两个服务端数据库的命名卷独立于容器生命周期。
